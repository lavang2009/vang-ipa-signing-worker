# VANG STORE IPA Worker — current upload architecture (2026-11-15)

The original multipart `/v1/sign` route is retained for backwards compatibility only. The current Website must not send large IPA files to that endpoint.

## Current flow

1. Website splits IPA (maximum configured size 512 MiB) and certificate ZIP (20 MiB) into 3 MiB chunks.
2. Website route `POST /api/ipa-signing/chunk` authenticates the Firebase ID Token and writes chunks to a Private Vercel Blob Store.
3. Browser sends only JSON metadata to Worker `POST /v1/sign-blob`.
4. Worker verifies Firebase identity, reconstructs files from private Blob chunks, validates IPA and certificate ZIP, and runs ZSign.
5. Worker writes the signed IPA to private Blob and returns a signed download URL. Input chunks are deleted after processing; abandoned uploads expire through Blob TTL.

Each multipart chunk request remains below the Vercel Functions request body limit. Chunk upload does not remove platform execution-time, temporary-storage, memory, or overall Blob constraints.

See `README-VERCEL.md` for current environment variables, shared-Blob requirement, CORS behavior, health diagnostics, and deployment steps.
